# posixre

一个只依赖 Python 3.11 标准库的小型正则引擎库。两个设计目标：

1. **匹配耗时可预测**：底层是 Thompson NFA 的集合模拟（带捕获标签），
   最坏耗时为 `O(n · |Q| · G)`，其中 `n` 是文本长度、`|Q|` 是模式展开后
   的状态数、`G` 是捕获组数；后两者只由模式决定。不存在回溯，因此不会
   出现 `(a|aa)*b`、`(a+)+b` 这类嵌套量词在 Python `re` 上的指数级爆炸。
2. **POSIX 最左最长捕获语义**：不是 Python/Perl 的最左优先。

本包只提供库接口，没有命令行入口。

## 接口

```python
import posixre

# 编译
p = posixre.compile(r"(\d+)-(\d+)")

# 单次匹配：在文本中搜索最左最长匹配
m = p.match("call 867-5309")
# 或模块级：posixre.match(pattern, text)

m.span()        # (5, 13)   组 0 = 整条匹配
m.span(1)       # (5, 8)
m.group(2)      # '5309'
m.groups()      # ('867', '5309')
m.start(1)      # 5
m.end(1)        # 8

# 全局扫描：所有不重叠匹配
for m in posixre.finditer(r"\w+", "a b  c"):
    ...
# 或编译后：p.finditer(text)
```

`Match.span(g)` 对未参与匹配的可选组返回 `None`；参与但匹配空串的组
返回 `(x, x)`。

`Pattern.match(text, pos=0, endpos=None)` 还支持在 `text[pos:endpos]`
窗口内搜索，返回的位置是相对整个 `text` 的绝对位置，内部不复制字符串。

## 支持的语法

| 写法 | 含义 |
| --- | --- |
| `a` `1` `字` | 字面字符（元字符需用 `\` 转义） |
| `.` | 任意单个字符，**包括换行** |
| `[abc]` `[a-z0-9_]` | 字符类与区间 |
| `[^abc]` | 取反字符类 |
| `\d \w \s` 与 `\D \W \S` | 数字/单词/空白及其补集，类内类外均可用 |
| `ab` | 连接 |
| `a|b` | 选择 |
| `*` `+` `?` | 零或多 / 一或多 / 零或一，只有贪婪语义 |
| `{n}` `{n,}` `{n,m}` | 计数量词 |
| `(...)` | 捕获分组，编号按左括号次序 |
| `(?:...)` | 不捕获分组 |
| `^` `$` | 锚定**整个字符串**的开头 / 结尾（不是行首行尾） |
| `\n \t \r \f \v \a \0 \xHH \uHHHH` | 常见转义 |

孤立的 `{`、`}` 当普通字面字符；不是合法量词的 `{...}` 也按字面处理。

## 编译期拒绝的写法（报错含字符位置）

以下特性本次不做，在**编译阶段**直接抛 `posixre.PatternError`。
异常的 `pos` 属性是 0 基下标，消息里同时给出“第几个字符”：

* 反向引用：`\1`…、`(?P=name)`
* 各类环视：`(?=…)` `(?!…)` `(?<=…)` `(?<!…)`
* 单词边界：`\b`（字符类内的 `[\b]` 仍表示退格）、`\B`
* 非贪婪 / 占有量词：`a*?`、`a++`
* 命名分组、原子分组、条件表达式、注释分组等

```python
try:
    posixre.compile(r"a\1")
except posixre.PatternError as e:
    print(e.pos, e)   # 1  本子集不支持反向引用 (\1)（第 2 个字符，0 基下标 1）
```

## POSIX 最左最长语义

先确定**最左**的起点，再让整条匹配**最长**；整体长度相同时，让编号小的
捕获组尽可能长。这与 Python `re` 的最左优先不同。

经典对照（Russ Cox 文章中的例子）：

```
模式 (a|ab)(c|bcd)(d*)   文本 abcd

Python re（最左优先）：('a', 'c', 'd')
posixre（最左最长）  ：('ab', 'c', 'd')
```

被量词重复的捕获组记录其**最后一次参与**的区间，例如
`(ab)*` 匹配 `ababab` 时组 1 为 `(4, 6)`。

捕获位置由 NFA 线程上携带的标签随模拟一起算出，取分组位置不会引入回溯，
与“是否匹配”在同一遍线性模拟内完成。

## finditer 的空匹配推进规则

从头到尾产出**不重叠**匹配：

1. 从当前游标 `pos` 找下一个匹配 `[s, e)`（`s >= pos`）；
2. 下一轮搜索从 `e` 开始；
3. 若该匹配是空匹配（`s == e`），则先把游标强制推进到 `e + 1`，
   即跳过 `text[e]` 这一个字符再继续——该字符不属于任何匹配，也不会再
   被当作匹配起点。这样保证不会在同一个位置反复产出空串，也不会连续产出
   两个落在同一位置的空匹配；
4. 游标越过文本末尾即停止；**允许在末尾位置产出一个空匹配**。

例如：

```
posixre.finditer("a*", "aba")  的 span 序列：
  (0,1)="a"   (1,1)=""   (2,3)="a"   (3,3)=""
            ↑ 空匹配，跳过位置 1 的 'b'

posixre.finditer("", "ab")    ：(0,0)  (1,1)  (2,2)
```

## 耗时说明

单次 `match` 最坏 `O(n·|Q|·G)`，`finditer` 对整段文本是线性扫描
（按上述推进规则逐段调用线性匹配，各段长度之和为 O(n)）。
对 `(a|aa)*b` 配 20/40/60/80 个 `a` 均在毫秒级给出“不匹配”，
长度翻番时耗时近似翻番，不随嵌套量词指数增长；放大到上万字符仍保持
每字符耗时基本恒定。
