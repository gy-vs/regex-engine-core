# posixre

一个**不回溯、匹配耗时可预测**的正则引擎，纯 Python 3.11 标准库实现，只有库、没有命令行入口。

## 对外接口

```python
from posixre import compile, match, scan

p = compile(r"(a|ab)(c|bcd)(d*)")
m = p.match("abcd")          # 单次匹配，返回 Match 或 None
m.span()                     # (0, 4)  整体匹配
m.groups()                   # ('ab', 'c', 'd')
m.span(1)                    # (0, 2)  第 1 个捕获组起止
list(scan(r"\w+", "ab cd"))  # 从头到尾扫描所有不重叠匹配
```

* `compile(pattern)` 编译模式，返回 `Pattern`；
* `match(pattern, text)` / `Pattern.match(text, anchored=False)` 单次匹配；
* `scan(pattern, text)` / `Pattern.scan(text)` 迭代所有不重叠匹配。

`Match` 提供 `span / start / end / group / groups / groupspans`。未参与匹配的组
（比如另一个分支里的组）返回 `None`；参与了但匹配空串的组返回 `(s, s)`。

## 支持的语法

* 字面字符与反斜杠转义：`\n \t \r \f \v \a \0 \xHH`，以及 `\. \\ \( \) \[ \]
  \^ \$ \| \* \+ \? \{ \}` 等；
* `.` 点号；
* 方括号字符类：区间 `[a-z]`、取反 `[^0-9]`，简写 `\d \D \w \W \s \S`
  也可以出现在类内；`[]a]` 的首字符 `]` 按字面处理，开头/结尾的 `-` 也是字面；
  类内的 `\1`–`\377` 是八进制字符值（类内没有反向引用），类内 `\b` 是退格；
* 连接、`|` 选择（允许空分支）；
* 量词 `* + ?` 和花括号计数 `{m}`、`{m,}`、`{m,n}`；
* 圆括号分组：捕获 `(...)` 和不捕获 `(?:...)`；
* 锚点：`^` 仅匹配整个字符串开头，`$` 仅匹配结尾；另支持 `\b` / `\B` 词边界；
* `\w \d \s` 按 Python 的 Unicode 定义（`isalnum` 加下划线、`isdecimal`、`isspace`）。

**反向引用和环视不做**：`\1`–`\9`、`\k<...>`、`(?=...)`、`(?!...)`、
`(?<=...)`、`(?<!...)` 在**编译阶段**直接抛 `posixre.error`。异常对象的 `pos`
是从 0 开始的字符下标，错误信息里的“第 N 个字符”是从 1 开始数的：

```
backreferences are not supported (at pattern character 4)
look-around assertions are not supported (at pattern character 3)
```

## POSIX 最左最长语义

捕获按 POSIX **最左最长**，而不是 Python/Perl 的最左优先：

1. 先选最靠左的起点；
2. 起点相同选整体匹配最长的终点；
3. 整体长度相同，再按开括号顺序（外层组优先于内层、靠前的组优先于靠后的组），
   让每个组“参与匹配优先于不参与，匹配更长优先于更短，等长时起点更左优先”。

关键例子 `(a|ab)(c|bcd)(d*)` 匹配 `abcd`：最左优先会让第一组拿 `a`，本引擎
按 POSIX 给出 `('ab', 'c', 'd')`。被量词重复的捕获组保留**最后一次迭代**
的位置（POSIX 惯例：一次迭代没进该组不会清空更早迭代记录的值）。

## 复杂度与实现

匹配是**带标签的 Thompson NFA 模拟**，完全不回溯：

* 每个输入字符做一次“epsilon 闭包 + 字符推进”，时间
  `O(文本长度 × 程序规模)`，再乘以一个只与捕获组数有关的小因子，**不会**随量词
  嵌套指数增长；
* 捕获位置作为标签挂在 epsilon 边上。同一 NFA 状态上若多个线程汇合，保留按
  POSIX 组顺序互不支配的前沿（antichain）；组一旦闭合，更长的分配立即支配更短
  的，前沿随之塌缩——前沿规模由捕获组结构界定，不随解析路径数增长。因此拿捕获
  位置不需要退回回溯；
* 经典病态模式 `(a|aa)*b` 配 `a`×80（无 `b`）不匹配，实测约 0.5 毫秒；
  20/40/60/80 四个长度耗时随长度线性增长（见 `tests/test_performance.py`）。

## scan 的空匹配推进规则（用于核对）

`Pattern.scan` 从头到尾产生**不重叠**匹配，规则与标准非重叠 finditer 约定一致，
保证空匹配不会让扫描卡在同一位置：

1. 非空匹配之后，从该匹配的结束位置继续找；
2. 在非空匹配结束位置上若只找到**空匹配**，则跳过这个空匹配（它和上一个匹配
   终点同位），指针再前进一个字符后继续；
3. 实际产出了一个**空匹配**之后，指针恰好前进一个字符；若空匹配位于文本末尾，
   产出该空匹配后扫描结束；
4. 因而相邻两个匹配永远不会占据同一位置，每个字符至多被跳过一次。

例：

| 模式   | 文本  | scan 结果                               |
|--------|-------|-----------------------------------------|
| `a*`   | `bab` | `(0,0), (1,2), (3,3)`                   |
| `a*`   | `aa`  | `(0,2)`（结尾同位空匹配被抑制）         |
| `x*`   | `ab`  | `(0,0), (1,1), (2,2)`                   |
| `\|bc` | `abc` | `(0,0), (1,3)`                          |

## 测试

只用标准库 `unittest`，不用 re/regex 做对照（捕获语义不同）。
`tests/oracle.py` 是独立的暴力 POSIX 枚举参照器，`tests/test_differential.py`
用上千个随机模式/文本（含重叠分支、嵌套量词、锚点）对引擎做差分验证：

```
python3 -m unittest discover -s tests
```
